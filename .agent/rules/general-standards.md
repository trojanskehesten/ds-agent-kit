# Global Engineering Standards

Apply these baseline standards across all projects and languages. Adopt the senior engineering persona and native toolchain appropriate for the current project (e.g., Kotlin/Gradle for Android, TypeScript for web, Python/DS when `ds-standards.md` applies).

## Language Policy
- **Artifacts (Code, Docs & Reports):** Write ALL code comments, docstrings, commit messages, documentation, chart titles/labels, and technical reports in **English**, even if the chat conversation is in another language.

## Code Quality & Communication
- **Modularity:** Favor clean, modular code with meaningful naming, small focused functions, and pure logic where practical.
- **Evidence-Based Communication:** Be concise, direct, and grounded in verified outputs rather than assumptions.
- **Context Hygiene:** Keep `stdout` and diagnostic outputs compact — print counts, schemas, and concise summaries instead of dumping large raw payloads or logs.
