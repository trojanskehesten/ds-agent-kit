# Подключение AI-агента к JupyterLab и VS Code (через MCP)

> **Перед установкой проверьте возможности своего агента.** Инструкция ниже рабочая, но нужна только в том случае, если ваш AI-агент не умеет нативно править ячейки и выполнять код в живом ядре ноутбука (или вам не хватает его встроенных возможностей). Многие современные инструменты — например, **GitHub Copilot**, **Claude Code** (в связке с VS Code: `NotebookEdit` + `executeCode` с подтверждением запуска) и **Cortex Code** — уже закрывают эти задачи из коробки.

## Зачем нужен этот сетап и в чём проблема

Прямая работа AI-агента с обычными файлами `.ipynb` на диске быстро становится неудобной и дорогой по трём причинам:

1. **Перерасход токенов и хрупкость формата.** Файл `.ipynb` — это сырой JSON с метаданными, экранированием и встроенными выводами ячеек. Пара графиков в `base64` или больших HTML-таблиц внутри ноутбука легко сжигает десятки тысяч токенов при каждом чтении, а любая ошибка правки ломает структуру JSON.
2. **Слепота агента к живому ядру.** Редактируя файл на диске, агент не может сам запускать ячейки, не видит переменные в памяти (RAM) и не получает `stdout` или `traceback` из текущей сессии — ошибки и результаты приходится копировать в чат вручную.
3. **Конфликты синхронизации в браузере.** При работе в JupyterLab интерфейс по умолчанию не подхватывает внешние изменения файла в реальном времени: приходится постоянно нажимать `Reload` или сталкиваться с окнами конфликта `Overwrite`.

Подключение **`jupyter-mcp-server`** решает первые две проблемы: агент получает прямой доступ к живому ядру и отдельным ячейкам без чтения сырого JSON. *(Учтите, что сами описания MCP-инструментов тоже занимают заметный объём контекста, поэтому экономия токенов ощутима в первую очередь на тяжёлых ноутбуках с выводами и графиками, а не на маленьких чистых файлах.)* Для работы API самого MCP-сервера (чтение и редактирование ячеек) в обоих сценариях также требуется расширение **`jupyter-collaboration`** на стороне сервера, которое в JupyterLab заодно даёт синхронизацию в реальном времени.

## Общая подготовка

1. **Установите `uv` глобально** (чтобы команда `uvx` была доступна MCP-клиенту из любого окружения, а не только внутри активированного `.venv`):
   * Windows: `winget install astral-sh.uv`
   * macOS / Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`

   *(После установки перезапустите терминал и IDE, чтобы обновился `PATH`.)*

2. **Добавьте служебные файлы `jupyter-collaboration` в `.gitignore`:**
   ```gitignore
   .jupyter_ystore.db*
   .jupyter/
   ```

## Сценарий 1 (основной): Работа с ноутбуком в браузере (JupyterLab)

1. **Активируйте `.venv` и установите пакеты:**
   ```bash
   uv pip install jupyterlab jupyter-collaboration jupyter-mcp-tools ipykernel
   ```
   *(Если окружение создано без `uv`, используйте `pip install ...`. Пакет `jupyter-mcp-tools` — опциональное расширение, добавляющее команды уровня JupyterLab вроде запуска всех ячеек.)*

2. **Запустите JupyterLab в отдельном терминале из корня проекта:**
   ```bash
   jupyter lab --port 8888 --IdentityProvider.token YOUR_RANDOM_TOKEN
   ```

3. **Подключите MCP-сервер** в конфиге вашего AI-агента и перезагрузите клиент (см. раздел ниже).

4. **Откройте ноутбук во вкладке JupyterLab и подключите агента:**
   Когда ноутбук открыт в браузере, у него уже есть живая сессия. Искать `kernel_id` вручную не нужно — просто попросите агента в промпте:
   > Подключись через `use_notebook` к `<путь_к_ноутбуку_от_корня>`.

   MCP-сервер автоматически подхватит живое ядро открытой вкладки, а все правки агента будут отображаться в интерфейсе JupyterLab в реальном времени.

## Сценарий 2: Работа с ноутбуком внутри IDE (VS Code и совместимые редакторы)

> **Важно:** этот сценарий нужен, если вы хотите работать с ноутбуком прямо внутри редактора в IDE/агентах без нативной связки с его ядром (например, в **Antigravity**, **Cursor**, **Codex** и других MCP-клиентах), либо если встроенных инструментов агента недостаточно для автономной работы с ноутбуком.

1. **Активируйте `.venv` и установите пакеты:**
   ```bash
   uv pip install jupyter-server jupyter-collaboration ipykernel
   ```
   *(Если окружение создано без `uv`, используйте `pip install ...`. Пакет `jupyter-collaboration` здесь нужен не для интерфейса редактора, а для работы MCP-сервера с ячейками — без него их чтение и запуск падают с ошибкой `404`; `execute_code` работает и без него.)*

2. **Запустите локальный Jupyter-сервер в отдельном терминале из корня проекта:**
   ```bash
   jupyter server --no-browser --port 8888 --IdentityProvider.token YOUR_RANDOM_TOKEN
   ```

3. **Подключите MCP-сервер** в конфиге вашего AI-агента и перезагрузите окно IDE / MCP-клиент (см. раздел ниже).

4. **Привяжите ноутбук в редакторе к запущенному серверу:**
   * Откройте `.ipynb` в VS Code (или совместимой IDE).
   * В правом верхнем углу ноутбука нажмите **Select Kernel → Select Another Kernel... → Existing Jupyter Server...**.
   * Вставьте `http://localhost:8888/?token=YOUR_RANDOM_TOKEN`, нажмите `Enter` и выберите ядро вашего `.venv` (часто отображается как `Python 3 (ipykernel)`).

5. **Передайте агенту `kernel_id` для общей памяти:**
   Расширение Jupyter в VS Code создаёт сессию с синтетическим путём вида `name-jvsc-<uuid>.ipynb`, поэтому MCP-сервер сам не сопоставит её с файлом и агент окажется не в вашем ядре. Чтобы подключить агента именно к вашему ядру, выполните в ноутбуке ячейку:
   ```python
   import ipykernel; print(ipykernel.get_connection_file())
   ```
   Возьмите ID из имени файла `kernel-<id>.json` и в первом промпте укажите агенту:
   > Подключись через `use_notebook` к `<путь_к_ноутбуку_от_корня>` с `kernel_id=<id>`.

   *(После смены ядра, перезагрузки окна или переподключения получите `kernel_id` заново — он мог измениться.)*

> **Нюанс VS Code:** редактор сохраняет ноутбук напрямую на диск, а не через протокол collaboration, поэтому включите автосохранение (`files.autoSave`) и не редактируйте ячейки одновременно с агентом, чтобы не перезаписать правки друг друга.

## Подключение MCP-сервера и проверка (общее для обоих сценариев)

1. **Добавьте сервер `jupyter` в конфигурацию MCP вашего AI-агента или IDE:**
   Базовый формат (JSON):
   ```json
   {
     "mcpServers": {
       "jupyter": {
         "command": "uvx",
         "args": ["jupyter-mcp-server@latest"],
         "env": {
           "JUPYTER_URL": "http://localhost:8888",
           "JUPYTER_TOKEN": "YOUR_RANDOM_TOKEN",
           "ALLOW_IMG_OUTPUT": "false"
         }
       }
     }
   }
   ```
   * Точный путь и формат конфига зависят от клиента (например, `mcpServers` в Claude Code / Cursor / Antigravity, `servers` с `"type": "stdio"` в `.vscode/mcp.json`, либо TOML-секция `[mcp_servers.jupyter]` в Codex).
   * Замените `YOUR_RANDOM_TOKEN` на свой случайный токен, не открывайте сервер наружу (`--ip 0.0.0.0`) без необходимости и не коммитьте локальный MCP-конфиг с токеном в Git (в клиентах с поддержкой переменных окружения, например Claude Code, используйте `${JUPYTER_TOKEN}`).
   * Флаг `ALLOW_IMG_OUTPUT: "false"` отключает передачу картинок графиков агенту — это экономит токены, но агент не будет видеть графики визуально.
   * Для стабильной работы вместо `@latest` можно зафиксировать конкретную проверенную версию (например, `jupyter-mcp-server==2.2.6`).

2. **Перезагрузите окно IDE или перезапустите MCP-клиент** и убедитесь, что сервер `jupyter` подключился без ошибок.

3. **Быстрая проверка общей памяти:** выполните в ноутбуке ячейку (не выводя переменную на экран):
   ```python
   import secrets; probe = secrets.token_hex(4)
   ```
   Попросите агента (после `use_notebook`) выполнить `print(probe)` через `execute_code`, а затем выполните `print(probe)` в ноутбуке сами. Если значения совпали — сервер, `jupyter-collaboration` и общая память настроены правильно (`NameError` означает, что агент подключился к другому ядру).

> **Важно при работе:** когда ноутбук подключён через MCP, агент должен создавать и редактировать ячейки **только** инструментами MCP (`insert_cell`, `edit_cell_source`, `overwrite_cell_source` и т.д.), а не обычными файловыми инструментами (`edit_file` / прямой записью в `.ipynb` на диск) — иначе сервер `jupyter-collaboration` перезапишет или проигнорирует внешние правки и возникнет рассинхрон.

## Альтернатива: `jupytext`

**`jupytext`** (в JupyterLab — также лучше в связке с `jupyter-collaboration`, а в VS Code можно просто запускать `.py`-файлы с разделителями `# %%` через встроенное Interactive Window) стоит выбирать, когда вам нужен жёсткий ручной контроль над запуском кода, чистые diff'ы в Git и максимальная экономия токенов — например, при рефакторинге, код-ревью или работе с тяжёлыми пайплайнами, где нежелательно, чтобы агент сам перезапускал ячейки.

* **Плюсы:** минимальный расход контекста (агент работает с чистым `.py` без JSON-разметки, `base64`-графиков и схем MCP-инструментов), прозрачная история изменений в Git и отсутствие настройки MCP.
* **Минусы:** агент не имеет доступа к живому ядру и переменным в памяти текущей сессии (код он может запускать только отдельно через терминал), а в браузерном JupyterLab без `jupyter-collaboration` приходится вручную перезагружать ноутбук с диска.
